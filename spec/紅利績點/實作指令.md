# 實作與資料庫操作指令

本文件供後續實作使用，不代表已執行。先確認 [計畫書](./計畫書.md) 的待確認事項，再審查並調整 [資料庫指令.sql](./資料庫指令.sql)。

## 執行順序

1. 完成會員 session、訂單狀態機、累點／折抵／到期／退款及測試設計；確定依賴版本及安全的密碼雜湊方案後再更新 `requirements.txt`。
2. 將 SQL 草案改寫為應用程式管理的**版本化遷移**。確認目前 schema 和遷移版本後，於單一寫入交易中執行；成功後才記錄版本。不能對相同資料庫再次執行 `ALTER TABLE`。
3. 首次啟用時由部署程序明確建立規則版本：10 元取得 1 點、100 點折 1 元、效期 12 個月；指定 UTC 生效時間。規則不可回頭覆寫已引用版本。
4. 停止所有應用程式寫入，使用 SQLite backup API 備份，於備份副本測試遷移；不要在服務仍寫入時只複製主檔，否則可能遺漏 WAL 資料。
5. 執行相容性及完整性檢查後才部署程式和遷移；不可讓舊程式在遷移後繼續寫入而未填 `payable_amount`。失敗時停止寫入並以完整備份還原；不得以刪欄方式回復而遺失新訂單。

## 範例：安全備份（PowerShell，僅供後續操作）

先自行確認目的地不存在，並於專用維護時段執行；此範例不會被本文件自動執行：

```powershell
@'
import sqlite3
from pathlib import Path

source = Path("data") / "pos.db"
backup = Path("data") / "pos-before-loyalty.db"
if not source.is_file():
    raise SystemExit("來源資料庫不存在")
if backup.exists():
    raise SystemExit("備份檔已存在，請選擇其他名稱")
with sqlite3.connect(f"{source.resolve().as_uri()}?mode=ro", uri=True) as src:
    with sqlite3.connect(backup) as dst:
        src.backup(dst)
print(f"備份完成：{backup}")
'@ | python -
```

不要直接執行 SQL 草案於 `data\pos.db`；先以測試程式在記憶體或備份副本套用。正式操作必須由具版本檢查及完整錯誤處理的遷移程式負責，不能把草案當成可重跑腳本。

## 驗證指令與檢查

- 在遷移連線及所有應用連線啟用 `PRAGMA foreign_keys = ON`；驗證連線值為 1。
- 遷移後執行 `PRAGMA foreign_key_check`，預期零筆；執行 `PRAGMA integrity_check`，預期 `ok`。
- 比對遷移前後訂單數、明細數、訂單總額及每筆舊訂單 `payable_amount = total_amount`、`member_id IS NULL`；再確認無新會員或點數資料被意外產生。
- 對隔離的測試資料庫執行新舊版 API、並發和交易回滾測試，以及計畫書的驗收案例；不得對正式資料呼叫測試的訂單、退款或登入 API。
- 確認到期與折抵計算使用同一個可信時間及資料庫交易，並確認帳本、批次及分配明細能對帳。規則變更不可改寫歷史紀錄。
- 執行專案既有測試，例如在專案根目錄執行 `python -m unittest discover -s tests`；實際實作時先確認環境及測試工具，再執行相關新增測試。

## 預計 API

以下路徑與回應為規劃，實作前可依現有規範調整：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| POST | `/api/members/register` | 手機與密碼註冊；避免洩露帳號是否存在。 |
| POST | `/api/members/login` | 登入並建立會員 session。 |
| POST | `/api/members/logout` | 撤銷 session 並清除 cookie。 |
| GET | `/api/members/session` | 取得目前會員登入狀態。 |
| GET | `/api/members/me/points` | 查詢本人可用點數及即將到期批次。 |
| GET | `/api/members/me/points/transactions` | 分頁查詢本人點數異動。 |
| POST | `/api/orders` | 保留原訪客輸入，依 session 綁定會員；會員可選擇折抵點數。 |

查詢 API 不接受會員 ID 作為授權依據。API 的具體回應欄位、分頁及到期區間於實作時明確定義並測試；未登入點數查詢回傳 401。會員 session cookie 路徑須涵蓋 `/api/orders`，不能直接沿用只涵蓋 `/api/admin` 的管理員 cookie。
