# 會員及紅利點數功能計畫

狀態：已依確認的規則實作。資料庫沿用 `data/pos.db`；本目錄的 SQL 是原始設計草案，不可直接用於正式環境，實際結構與遷移以 `src/loyalty_schema.py` 為準。

## 需求與範圍

- 保留免登入訪客下單；原有 `/api/orders` 的桌號及餐點輸入維持相容，訪客訂單的 `member_id` 為 NULL。
- 會員以手機號碼及密碼登入；登入後建立的訂單由伺服器根據有效會員 session 綁定會員，不接受客戶端指定會員 ID。
- 會員可查詢自己可用點數、即將到期點數及分頁異動紀錄。訪客不累點，既有訪客訂單不自動補綁或補點。
- 每消費 10 元得 1 點，100 點折抵 1 元；每筆取得的點數自取得日起 12 個月到期。金額與點數均以整數儲存。
- 訂單須同時為 `completed` 且 `paid` 才累點。折抵後實際付款金額為累點基礎，零頭不足 10 元捨去。
- 一般點餐、菜單、管理員登入與既有儀表板應維持原有行為；點數折抵的商品營收如何呈現，見待確認事項。

## 資料庫設計

完整關聯見 [ERD.mmd](./ERD.mmd)，欄位與限制草案見 [資料庫指令.sql](./資料庫指令.sql)。

| 表 | 用途 |
| --- | --- |
| `members` | 唯一正規化手機號碼、密碼雜湊、姓名及狀態。停用而非直接刪除，避免破壞歷史紀錄。 |
| `member_sessions` | 會員 session token 的雜湊、效期及撤銷時間；不儲存原始 token。與店家管理員 session 分開。 |
| `member_login_attempts` | 記錄手機及來源 IP 雜湊的登入失敗次數，以 15 分鐘為時間窗限制嘗試。 |
| `schema_migrations` | 記錄已完成的資料庫遷移版本。 |
| `loyalty_rules` | 保存累點、折抵、效期規則的版本及生效時間；交易引用當時規則，避免規則改變影響歷史。初始規則應於正式啟用時建立。 |
| `point_transactions` | 不覆寫的點數異動帳本，記錄會員、訂單、規則、正負點數、異動類型、原交易、冪等鍵及建立時間。 |
| `point_lots` | 每筆正向入點批次的原始點數、剩餘點數及到期時間；由來源交易建立。 |
| `point_redemption_allocations` | 折抵交易分配至各點數批次的數量；讓退款時能追溯原始批次與效期。 |

`orders` 新增可空的 `member_id`、預設為零的 `points_redeemed` 與 `points_discount_amount`，以及 `payable_amount`。原 `total_amount` 仍為折抵前總額；既有訂單 `payable_amount` 回填為 `total_amount`。應用程式必須對新訂單寫入應付金額；草案允許 NULL 以免舊版程式下單立即失敗，部署時須防止舊版與新版混用。

不另存 `members.points_balance` 快取：可用餘額由未過期 `point_lots.remaining_points` 加總，避免未執行到期作業時顯示過期點數。帳本與批次餘額必須在同一交易更新並定期對帳；人工調整、沖銷及到期也需同步更新批次。已用或過期點數不可使用。

## 程式調整

1. **資料庫與遷移**：調整 `src/database.py`，加入版本化且可重複啟動的遷移；所有寫入連線開啟 `PRAGMA foreign_keys = ON`。不可依賴 `CREATE TABLE IF NOT EXISTS` 自動升級現有表。遷移前停寫、備份；驗證及回復程序見 [實作指令.md](./實作指令.md)。
2. **會員身分**：新增註冊、登入、登出及 session 查詢 API。正規化手機號碼並驗證唯一性，使用 Python 標準函式庫的 scrypt 密碼雜湊，不記錄密碼或原始 session token。限制登入嘗試、使用一般化錯誤訊息；cookie 設定 HttpOnly、SameSite，HTTPS 時設 Secure，並驗證狀態變更請求的 Origin。登入註冊及查詢應使用 HTTPS。
3. **下單與折抵**：維持原有訪客請求；會員由 session 解析。先由後端檢查有效會員、未過期點數、折抵比例及應付金額，於同一交易中按到期時間及批次 ID 排序扣點、寫入訂單、帳本和分配明細；不得超出餘額或訂單總額。失敗時全部回滾。客戶端不決定價格或會員 ID。
4. **狀態與累點**：修改 `src/admin.py` 的訂單更新流程，鎖定並讀取舊狀態，驗證狀態轉換，以交易原子更新狀態與點數。訂單首次達成已完成且已付款條件時，按當時規則寫入帳本並建立批次；唯一冪等鍵及資料庫交易保護重試與並發。不可任意往返付款／訂單狀態造成重複累點。
5. **查詢與介面**：增加登入／註冊／登出及「我的紅利點數」介面；API 只以 session 查詢本人可用點數、到期批次及分頁交易。前端仍保留不登入下單入口。逾期批次即使排程尚未執行，也不得納入可用餘額或折抵。
6. **退款、取消、到期**：以反向交易記錄而不刪改歷史帳本；退款時依折抵分配回復原批次。已用掉或過期的累點、或已過期的折抵批次會拒絕退款／取消更新，需由店家處理。查點或折抵時以冪等方式記錄及扣除到期批次；即使尚未觸發到期作業，查詢和折抵也不包含過期點數。
7. **文件與測試**：實作時同步更新 `spec/早餐店規格/er.md`、`spec/早餐店規格/database-erd.mmd`、`spec/早餐店規格/backend.md` 及相關前端規格。使用獨立測試資料庫，不使用正式資料。

## 安全與資料完整性

- `member_sessions` token 應使用高強度隨機值；伺服器只保存雜湊，失效、撤銷或會員停用後不可登入查詢或綁單。
- 手機號碼涉及個資，查詢和日誌應最小化並遮罩；不以手機號碼單獨授權查詢、折抵或下單綁定。
- 時間以 UTC ISO 8601 儲存，介面顯示 `Asia/Taipei`；到期的月末及時區算法須確認後統一實作。
- SQL 的 CHECK、唯一索引和外鍵只是第一層；同會員跨表一致性、類型正負、每次分配總和、不可超額及規則版本有效性仍需應用程式交易驗證。帳本不可任意 UPDATE／DELETE，應以資料存取層及測試保護。
- 有會員或點數紀錄的訂單不得物理刪除；取消或退款保留訂單。所有與點數有關的操作使用同一 SQLite 連線、同一寫入交易，並處理鎖定及失敗回滾。

## 驗收項目

- 舊資料遷移後訂單、明細及總金額不變；原始訪客下單 API 和頁面不需登入即可運作。
- 手機唯一、密碼錯誤不能登入；停用、過期、登出 session 不能查點或綁單；會員不得讀取其他會員資料。
- 例如實付 199 元得 19 點；199 點最多折抵 1 元、扣除 100 點；低於 100 點不能折抵 1 元。依確認後規則測試上限與零頭。
- `completed`、`paid` 先後順序皆可；未同時滿足不累點；重複請求及併發不重複入帳、扣點或產生負餘額。
- 到期邊界、先到期先使用、跨批次折抵、到期作業重試與退款還原均符合確認後規則；過期點數不列可用餘額。
- 取消、退款及狀態非法轉換不留不一致的訂單、帳本或批次；模擬交易失敗後驗證回滾和對帳。

## 已確認的營運規則

- 可折抵至 0 元；每次以 100 點為單位，且不得超過應付金額。
- 取消或全額退款若涉及已使用／已過期累點或已過期折抵批次，拒絕狀態更新，由店家處理；不支援部分退款或負點數。
- 以台北時間取得日加 12 個曆月的相同時刻到期；遇月末不存在的日期取該月最後一天。顯示未來 30 天到期點數。
- 下單立即扣抵；未付款訂單不自動取消，點數保留至人工取消。未提供線上重設密碼，也不驗證手機所有權。
- 儀表板保留原本折抵前、含未付款訂單的統計，不代表實收。
